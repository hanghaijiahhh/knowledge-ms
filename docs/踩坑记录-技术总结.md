## 一、Spring 基础设施

### 1.1 UserContextUtil Bean 注入失败

**现象**：`knowledge-doc` 启动报 `NoSuchBeanDefinitionException: UserContextUtil`。

**根因**：`UserContextUtil` 提取到 `knowledge-common` 的 `com.myy.common.config` 包下，但 Spring Boot 的 `@ComponentScan` 默认只扫描启动类所在包。`com.myy.common` ≠ `com.myy.knowledgexxx`。

**修复**：创建 `CommonAutoConfiguration.java`（`@AutoConfiguration` + `@Import(UserContextUtil.class)`），并在 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 注册。利用 Spring Boot 3.x 自动配置机制，不依赖包扫描。

**知识点**：Spring Boot 3.x 的 `@AutoConfiguration` vs 传统 `@Configuration`；`AutoConfiguration.imports` 文件加载机制。

---

### 1.2 Gateway WebFlux 与 Spring MVC 冲突

**现象**：Gateway 启动报 `Spring MVC found on classpath, which is incompatible with Spring Cloud Gateway`。

**根因**：`knowledge-common` 依赖 `spring-boot-starter-web`（含嵌入式 Tomcat）。Gateway 引入 common 后 classpath 上同时存在 WebFlux 和 Spring MVC。

**修复**：将 common 依赖拆细：
```xml
<dependency>
    <groupId>org.springframework</groupId>
    <artifactId>spring-web</artifactId>        <!-- 只引入 web 注解/工具，不带 MVC -->
</dependency>
<dependency>
    <groupId>jakarta.servlet</groupId>
    <artifactId>jakarta.servlet-api</artifactId>
    <scope>provided</scope>                    <!-- 编译可用，不传递到下游 -->
</dependency>
```
`provided` scope 是关键——Gateway 模块不会继承 servlet API，避免冲突。

**知识点**：Maven 依赖传递；`provided` scope 行为；WebFlux（响应式/Netty）与 Spring MVC（Servlet/Tomcat）的不兼容原理。

---

### 1.3 Feign `lb://` 调用报 No Feign Client for loadBalancing

**现象**：`lb://knowledge-doc` 调用时报 `No Feign Client for loadBalancing defined`。

**根因**：Spring Cloud 2025.x 中 `spring-cloud-starter-openfeign` 不再自动引入负载均衡器。

**修复**：手动添加 `spring-cloud-starter-loadbalancer`。

**知识点**：Spring Cloud 版本演进——Netflix Ribbon 已维护模式，默认改用 Spring Cloud LoadBalancer。

## 二、Java 基础陷阱

### 2.1 Map.of() 抛 NullPointerException

**现象**：`AgentOrchestrator` 报 NPE，定位到 `Map.of("role", "assistant", "content", null, ...)`。

**根因**：Java 9+ `Map.of()` 返回 `ImmutableCollections.MapN`，构造函数对所有 value 执行 `Objects.requireNonNull()`。但 OpenAI Function Calling 协议要求 `assistant` 消息在有 `tool_calls` 时 `content` 必须为 `null`——合法业务需求被 Java API 设计拒绝。

**修复**：改用 `LinkedHashMap` 逐项 put，允许 null value。同时保持插入顺序（对 LLM prompt 字段顺序敏感）。

**知识点**：`Map.of()` / `List.of()` / `Set.of()` 全部拒绝 null；`HashMap` vs `LinkedHashMap`；为什么 OpenAI 设计 content 可为 null（减少 token 浪费）。

## 三、Elasticsearch

### 3.1 Date Format 不匹配导致搜索 500

**现象**：`Unable to convert value '2026-07-01' to java.time.LocalDateTime for property 'createTime'`。

**根因**：`@Field(format = DateFormat.date_hour_minute_second)` 注解后来加入，但 ES 索引在注解前已创建。已有数据为纯日期 `2026-07-01`，新 format 要求 `yyyy-MM-dd'T'HH:mm:ss`，Spring Data ES 读回时解析失败。

**修复**：删索引 → 重建正确 mapping → reindex 回填数据。新增 `POST /search/admin/reindex` 运维端点。

**知识点**：ES mapping 是 schema-on-write；`@Field` 注解只作用于索引创建时；生产环境应使用 index template 或 reindex + alias 切换处理 schema 变更。

---

### 3.2 Embedding 服务 OOM（Dense Vector 序列化）

**现象**：`knowledge-embedding` 消费 MQ 消息时 `OutOfMemoryError: Java heap space`。

**根因（三层叠加）**：
1. 逐 chunk `save()` → N 个 chunk = N 次 HTTP 往返 + N 次 JSON 序列化
2. `float[1024]` 向量 JSON 序列化后约 16KB，是普通文本字段的数十倍
3. 无 JVM 堆配置，默认堆不足以承载 dense_vector 批量写入

**修复**：
- 逐条 `save()` → `saveAll()` 批量写入
- JVM 参数 `-Xms256m -Xmx512m` + `-XX:+HeapDumpOnOutOfMemoryError`
- ES 客户端加超时配置防连接堆积
- ChunkService 修复死循环（见下文 3.3）

**知识点**：`float[1024]` 在 Java 中占 ~4KB，JSON 序列化膨胀到 ~16KB（每个 float → 15+ 字符）；批量写入减少的不只是网络 IO，还有 Jackson 序列化/反序列化的 CPU 和内存开销。

---

### 3.3 嵌入服务死循环 → 加剧 OOM

**现象**：ChunkService.split() 在文本长度恰好等于 maxSize 时无限循环。

**根因**：`end >= text.length()` 后，`start = end - overlap` 计算得 `500 - 50 = 450`，下次循环 `end = 450 + 500 = 950`（超出文本），但 subtring(450, 500) 重复添加同一个 chunk，`start` 始终为 450。

**修复**：添加 `if (end >= text.length()) break;` 和 `start <= 0 || start >= end` 双重守卫。

## 四、安全漏洞（面试高频）

### 4.1 搜索权限绕过 — 新用户能看到所有文档

**现象**：新注册用户搜索任何关键词都能看到 admin 的私有文档。

**根因**：`SearchServiceImpl` 权限过滤存在 **fail-open** 问题：
```java
// 有问题的代码
List<Long> visibleIds = getVisibleDocIds(userInfo);  // 新用户 → 空列表
if (!visibleIds.isEmpty()) {   // 空列表 → 跳过 filter
    b.filter(...)
}
// 不加 filter → ES 裸查返回全库文档
```
当用户无可见文档时 filter 被跳过，ES 返回**全部文档**。这是 **fail-open**（失败放行），安全设计大忌。

**触发场景**：新用户无权限、ACL 授权被全部撤销、Feign 调用失败返回空。

**修复**：改为 **fail-safe**——无权限直接返回空，不做查询：
```java
if (visibleIds.isEmpty()) {
    return emptyResult();   // 没权限 → 直接返回空
}
b.filter(...);              // 有权限 → 必走 filter
```

**面试要点**：
- 安全设计原则：**默认拒绝，显式放行**（deny-by-default）
- `fail-open` vs `fail-safe`
- OWASP Top 10 #1: Broken Access Control，这个 bug 是典型案例
- 防御性编程：永远假设边界条件会出问题（Feign 失败、新用户、空数据）

## 五、架构设计

### 5.1 热搜关键词与实际文档不匹配

**现象**：热搜榜出现大量关键词，点击后搜索结果为空或与文档无关。

**根因**：`SearchController.search()` 中 `recordSearch(keyword)` 在搜索执行**之前**调用——无论搜索有没有结果，关键词都被记入 Redis ZSet。

**修复**：先执行搜索，拿到 `total` 后判断：`total > 0` 才调用 `recordSearch()`。保证热搜榜上每个关键词都对应到实际可查的文档。

**知识点**：数据质量比数据量重要；搜索产品的热搜榜如果点进去没结果，用户体验极差。

---

### 5.2 MinIO Bucket 不存在 + Spring 循环引用

**现象**：文件上传报 `The specified bucket does not exist`。

**根因**：MinIO 的 `knowledge-docs` bucket 未创建。首次尝试在 `MinioConfig` 的 `@PostConstruct` 中调用本类的 `minioClient()` `@Bean` 方法，触发 `Requested bean is currently in creation` 循环引用错误。

**修复**：将 bucket 初始化逻辑提取到独立的 `MinioBucketInitializer` 组件，通过构造器注入已创建好的 `MinioClient`。依赖链清晰：`MinioConfig → MinioClient → MinioBucketInitializer`。

**知识点**：Spring `@PostConstruct` 中不能调用同类的 `@Bean` 方法（容器正在创建该 Bean）；基础设施组件（MinIO/ES/Redis）的自动初始化应放在独立 `@Component` 中。

## 六、前端

### 6.1 ACL 权限管理的 UX 设计迭代（三次重构）

**背景**：文档级 ACL 需要允许文档创建者为其他用户设置读/写/下载权限。后端 `DocAclController` 已有完整的 CRUD 接口，难点在前端交互设计。

**第一版（失败）**：手动输入用户 ID 的 `<el-input type=number>`。用户需要记住或查询目标用户的 ID 再填入，实际完全不可用。

**第二版（失败）**：改为 `<el-select>` 搜索选择用户 + 三个 `<el-checkbox>` + "授权"按钮的两区域布局（上：添加授权，下：已有授权表格）。问题：
- 用户不理解"选人 → 勾权限 → 点授权"的操作路径，以为选中就会自动同步
- 已有授权行的开关没有保存按钮，切换后无处提交
- `el-select` 的 `v-model` 是 `ref('')`（字符串）而 `el-option` 的 `:value` 是 `u.id`（数字），`filterable` 模式下类型不匹配导致选不中
- 多个 API 串行调用（先 `/auth/users` 再 `/doc/{id}/acl`），弹窗打开慢

**第三版（最终方案）**：单表内联编辑模式。
```
表格行：用户列 | 读(Switch) | 写(Switch) | 下载(Switch) | 操作(保存/移除)

已有行：显示用户名，Switch 切换即时自动保存（@change → POST API）
新建行：用户列变下拉框选择，Switch 设置权限，点"保存"提交
```
核心改进：
- **一张表完成所有操作**，不用切换视线
- **已有行 Switch 自动保存**，无需额外按钮
- **新建行**点"+ 添加用户权限"追加空行，选用户后点保存
- 已授权用户在新建下拉框中 `:disabled`，防止重复
- `aclUserId` 改为 `ref(null)` 匹配数字类型的 `u.id`
- `Promise.allSettled` 并行加载用户列表和 ACL 数据
- `v-loading` 的开关包在 `try-finally` 中防止转圈卡死

**知识点**：表单设计的渐进优化——从"让用户适配系统"到"让系统适配用户"；Element Plus `el-select` 的 `v-model` 类型一致性；`filterable` 模式下字符串/数字比较语义。

### 6.2 Vue `{{ }}` 在 HTML 属性中显示原始模板

**现象**：`思考过程 ({{ msg.thoughtTrace.length }} 步)` 显示为原始字符串。

**根因**：Vue `{{ }}` 只在文本内容节点生效，不能用于 HTML 属性值。

**修复**：`:title="'思考过程 (' + msg.thoughtTrace.length + ' 步)'"`。

## 七、常见面试追问

### Q: 这些坑中哪个最有代表性？

推荐**搜索权限绕过漏洞**：
- 跨 Java → Spring Cloud → Elasticsearch → 前端全链路
- 涉及安全设计原则（fail-open vs fail-safe）
- OWASP Top 10 #1 就是 Broken Access Control
- 体现从"功能跑通"到"安全可靠"的思维升级
- 修复简单但根因分析需要全链路理解

### Q: Map.of() NPE 也值得讲吗？

值得单独讲：
- 表面看是 API 选型错误
- 深层是对不可变集合设计约束的理解
- 更值得说的是"为什么 OpenAI 协议需要 content=null"→ Function Calling 的 token 优化考量

### Q: ES 索引 schema 变更在你们生产环境怎么处理？

小项目 delete + recreate + reindex。生产环境应：
- Index Template 预设 mapping，新索引自动匹配
- 或 reindex API：新建索引 → 迁移数据 → alias 切换
- 或设计时让 date 字段使用多 format：`yyyy-MM-dd'T'HH:mm:ss||yyyy-MM-dd`

### Q: 为什么不用 Spring Cloud Gateway 内置限流？

Gateway 的 `RequestRateLimiter` 是 Redis 令牌桶，适合入口 QPS 限制。本项目限流是业务语义级（如文档上传接口），需结合用户 ID 区分，用 AOP + 自定义注解实现。两者互补：Gateway 粗粒度，微服务内部细粒度。
