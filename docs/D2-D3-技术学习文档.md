## 二、D2：Spring Cloud Gateway 网关

### 2.1 核心概念

**Gateway 是什么？**
微服务架构的"单入口"。所有外部请求先到 Gateway，再由 Gateway 根据路径转发到对应的微服务。好处：
- 前端只需要知道一个地址（8080），不用记每个服务的端口
- 鉴权在网关统一做，下游服务不用重复写

**WebFlux 和 SpringMVC 的区别**
Gateway 基于 WebFlux（响应式），不是传统的 SpringMVC。

| | SpringMVC | WebFlux |
|---|---|---|
| 底层 | Tomcat + Servlet | Netty + Reactor |
| 线程模型 | 一个请求一个线程 | 事件驱动，少量线程 |
| 返回值 | `Object` | `Mono<T>` / `Flux<T>` |
| Filter | `javax.servlet.Filter` | `GlobalFilter` |
| 适用 | 业务服务（auth、doc等） | 网关 |

**关键冲突**：Gateway 不能引入 `spring-boot-starter-web`（带了 Tomcat），否则启动报错 "Spring MVC found on classpath"。这就是 D1 为什么 common 模块只放了 `spring-web` 而不是 `spring-boot-starter-web`。

### 2.2 AuthFilter 详解

```java
@Component
public class 
    mplements GlobalFilter, Ordered {
```

**GlobalFilter**：Gateway 提供的全局过滤器接口，所有经过网关的请求都会进入 `filter()` 方法。

**Ordered**：决定多个 Filter 的执行顺序。`getOrder()` 返回 `-100` 表示高优先级（数值越小越先执行）。

**白名单机制**：
```java
private static final List<String> WHITE_LIST = Arrays.asList(
    "/auth/login", "/auth/register", "/auth/logout"
);
if (WHITE_LIST.stream().anyMatch(uri::startsWith)) {
    return chain.filter(exchange);  // 直接放行
}
```
登录和注册不需要 token——用户还没登录哪有 token。

**JWT 校验流程**：
```java
// 1. 从 Header 拿 token
String authHeader = request.getHeaders().getFirst("Authorization");
// Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...

// 2. 解析 JWT
Claims claims = Jwts.parser()
    .setSigningKey(secret.getBytes())
    .parseClaimsJws(token)
    .getBody();
// 如果签名不对 → SignatureException
// 如果过期 → ExpiredJwtException

// 3. 用户信息写入 Header 传给下游
String userJson = JSON.toJSONString(claims);
String encoded = Base64.getEncoder().encodeToString(userJson.getBytes());
ServerHttpRequest newReq = request.mutate()
    .header("X-User-Info", encoded)
    .build();
return chain.filter(exchange.mutate().request(newReq).build());
```

**为什么要把用户信息写到 Header？**
下游微服务直接从 Header 解码拿用户信息，不需要再重复验 token。Gateway 已经验过一次了。

**响应式写响应体**（WebFlux 特有）：
```java
private Mono<Void> unauthorized(ServerHttpResponse response, String message) {
    response.setStatusCode(HttpStatus.UNAUTHORIZED);
    byte[] bytes = JSON.toJSONString(ResponseResult.fail(401, message)).getBytes();
    DataBuffer buffer = response.bufferFactory().wrap(bytes);
    return response.writeWith(Flux.just(buffer));
}
```
不能用 `response.getWriter().write()`——那是 Servlet API。WebFlux 必须用 `DataBuffer` + `Flux` 来写响应。

### 2.3 路由规则

```yaml
routes:
  - id: knowledge-auth       # 路由ID，随意命名
    uri: lb://knowledge-auth  # lb:// = 从Nacos获取实例 + LoadBalancer负载均衡
    predicates:
      - Path=/auth/**         # 匹配规则：/auth/xxx 的请求转发到 auth 服务
```

**`lb://` 的含义**：
- `lb` = LoadBalancer
- Gateway 从 Nacos 查到 `knowledge-auth` 的所有实例
- 使用轮询算法选择一台
- 如果某实例挂了，自动踢掉

**`Path=/auth/**`**：Ant 风格路径匹配。`**` 匹配任意层级路径。

### 2.4 CORS 跨域（WebFlux 版）

```java
@Bean
public WebFilter corsFilter() {
    return (exchange, chain) -> {
        // OPTIONS 预检请求直接返回 200，不继续走业务链
        if (request.getMethod() == HttpMethod.OPTIONS) {
            response.setStatusCode(HttpStatus.OK);
            return Mono.empty();  // 直接结束，不调 chain.filter
        }
        return chain.filter(exchange);
    };
}
```

**为什么用 `WebFilter` 而不是 `CorsWebFilter`？**两者都行，`WebFilter` 更灵活。如果用传统 `WebMvcConfigurer.addCorsMappings`——Gateway 不走 MVC，写了不生效。

### 2.5 Knife4j 聚合文档

```yaml
knife4j:
  gateway:
    strategy: discover  # 自动扫描 Nacos 里的服务，聚合它们的 Swagger 文档
```

效果：浏览器打开 `http://localhost:8080/doc.html` → 左上角下拉框切换不同服务的 API 文档。

## 三、D3：认证授权服务（Spring Security + JWT + MyBatisPlus）

### 3.1 Spring Security 核心配置

```java
@Bean
public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
    http
        .csrf(AbstractHttpConfigurer::disable)          // ①
        .sessionManagement(s -> s.sessionCreationPolicy(
            SessionCreationPolicy.STATELESS))             // ②
        .authorizeHttpRequests(auth -> auth
            .requestMatchers("/auth/login", "/auth/register").permitAll()  // ③
            .anyRequest().authenticated()
        )
        .formLogin(AbstractHttpConfigurer::disable)      // ④
        .httpBasic(AbstractHttpConfigurer::disable)      // ⑤
        .addFilterBefore(jwtFilter,                      // ⑥
            UsernamePasswordAuthenticationFilter.class);
    return http.build();
}
```

**每行解释**：

① **关闭 CSRF**：CSRF 是防止跨站请求伪造的，但前后端分离 + JWT 不需要它。CSRF 防御依赖于 Cookie-Session，而我们用的是无状态 Token。

② **无状态 Session**：不创建 `HttpSession`。每次请求都是独立的，服务器不存登录状态。状态全在 JWT Token 里。

③ **白名单**：`/auth/login` 和 `/auth/register` 不需要认证即可访问。

④ **关闭表单登录**：就是那个让你困惑的默认 `/login` 登录页，关掉！

⑤ **关闭 HTTP Basic**：浏览器弹出用户名密码弹窗的那套认证方式，也关掉。

⑥ **插入 JWT Filter**：在 Spring Security 默认的 `UsernamePasswordAuthenticationFilter` 之前执行我们的 `JwtAuthenticationFilter`。

### 3.2 认证流程详解

```
POST /auth/login {username, password}
            │
            ▼
    AuthController.login()
            │
            ▼
    authenticationManager.authenticate(
        new UsernamePasswordAuthenticationToken(username, password))
            │
            ▼
    DaoAuthenticationProvider（Spring Security 内部）
            │
            ├──→ UserDetailsServiceImpl.loadUserByUsername(username)
            │       └── 查数据库 sys_user 表 → 返回 LoginUser
            │
            └──→ BCryptPasswordEncoder.matches(password, user.password)
                    └── 密码比对
            │
            ▼
    认证成功 → 返回 Authentication 对象
            │
            ▼
    JwtTokenProvider.generateToken(userId, username)
    → 返回 JWT 给前端
```

**关键理解**：`AuthenticationManager.authenticate()` 是 Spring Security 的认证入口。它会自动：
1. 调 `UserDetailsService.loadUserByUsername()` 查用户
2. 用 `PasswordEncoder.matches()` 验密码
3. 都不需要你手动写这段逻辑

### 3.3 JWT 详解

**JWT 结构**：
```
eyJhbGciOiJIUzI1NiJ9.eyJ1c2VySWQiOjEsInVzZXJuYW1lIjoiYWRtaW4iLCJleHAiOjE3MTg1MjM2MDB9.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
│                      │                                                                          │
└── Header（算法）      └── Payload（数据：userId, username, 过期时间）                            └── Signature（签名，防篡改）
```

**三段 Base64 编码用 `.` 拼接**。任何人拿到 token 都能解码 Payload（所以不要放密码），但无法篡改——因为 Signature 是用密钥签名的，改一个比特签名就不匹配了。

```java
// 签发
Jwts.builder()
    .setClaims(Map.of("userId", 1, "username", "admin"))  // Payload
    .setExpiration(new Date(now + 24*3600*1000))           // 24小时后过期
    .signWith(SignatureAlgorithm.HS256, secret)             // HS256签名
    .compact();

// 校验
Jwts.parser()
    .setSigningKey(secret)
    .parseClaimsJws(token)    // 签名不对 → 抛异常；过期 → 抛异常
    .getBody();               // 返回 Payload
```

### 3.4 SecurityContextHolder

```java
// 登录成功后，Spring Security 把用户信息存到当前线程
SecurityContextHolder.getContext().setAuthentication(authentication);

// 之后任何时候都可以取
Authentication auth = SecurityContextHolder.getContext().getAuthentication();
String username = auth.getName();
```

**这是一个 ThreadLocal**。当前请求处理线程独享，线程结束自动清除。所以每次请求都要在 Filter 里重新设置。

### 3.5 OncePerRequestFilter

```java
@Component
public class JwtAuthenticationFilter extends OncePerRequestFilter {
```

**为什么用 OncePerRequestFilter 而不是普通 Filter？**

普通 Filter 可能在一次请求中被调用多次（比如请求转发、include 等场景），`OncePerRequestFilter` 保证每个请求只过滤一次。

### 3.6 BCrypt 密码加密

```java
@Bean
public PasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder();
}
```

**BCrypt 的特点**：
- 同一个密码每次加密结果不同（因为自动加随机盐）
- 不可逆——无法从密文反推明文
- 比对用 `matches(raw, encoded)` 而不是 `equals`

```
"admin123" → BCrypt → "$2a$10$N.zmdr9k7uOCQb376NoUnu..."（每次不同）
```

数据库里存的是 BCrypt 加密后的结果，即使数据库泄露攻击者也拿不到原始密码。

### 3.7 Gateway Filter vs Auth Service Filter 的职责分工

| | Gateway AuthFilter | Auth Service JwtAuthFilter |
|---|---|---|
| 位置 | 网关层 | 业务服务层 |
| 触发范围 | 所有经过网关的请求 | 仅 /auth/** 之外的本服务请求 |
| 做什么 | 验 JWT → 注入 Header → 放行 | 验 JWT → 设 SecurityContextHolder |
| 失败处理 | 返回 401 JSON | 返回 401 JSON |

**两个都能验 JWT，为什么都要？**
- Gateway 验：保护下游所有服务，坏请求在网关层就拦截了，不进业务服务
- Auth Service 自己的 Filter：auth 服务内部也需要知道当前用户是谁（比如 `/auth/info` 接口需要 Authentication 对象）

## 四、数据表设计

```sql
sys_user          sys_role          sys_user_role
┌──────────┐     ┌──────────┐      ┌──────────────┐
│ id       │     │ id       │      │ id           │
│ username │     │ role_name│◄─────│ user_id (FK) │
│ password │     │ role_code│─────►│ role_id (FK) │
│ status   │     │ status   │      └──────────────┘
└──────────┘     └──────────┘
```

**ER 关系**：用户 ←→ 角色（多对多），通过 `sys_user_role` 关联表。

**为什么角色编码（role_code）可以当权限用？**
`ROLE_ADMIN`、`ROLE_USER` 这些编码直接作为 Spring Security 的 `GrantedAuthority`。后续配合 `@PreAuthorize("hasRole('ADMIN')")` 做方法级权限控制。

## 六、关键面试知识点

1. **为什么用 JWT 而不是传统 Session？**
   - 无状态，服务器不存 session，水平扩展方便
   - 适合微服务架构，token 可以在服务间传递
   - 缺点：无法主动失效（需配合 Redis 黑名单）

2. **Gateway + Auth Service 双验 Token 会重复吗？**
   - 不会。Gateway 先拦掉明显非法的请求（减轻下游压力），Auth Service 再验一次保证自身安全
   - 这符合"纵深防御"原则——每层都做校验

3. **CSRF 为什么可以关？**
   - CSRF 攻击利用的是浏览器自动带 Cookie 的特性
   - JWT 存 localStorage，不会自动发送，必须手动加到 Header
   - 攻击者无法构造带正确 Authorization Header 的跨站请求

4. **BCrypt 的盐存在哪？**
   - 存在密文本身里。`$2a$10$salt_hash` —— `10` 是加密轮数，后面跟着盐和哈希值
