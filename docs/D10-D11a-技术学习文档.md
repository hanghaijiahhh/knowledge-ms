## 二、为什么需要水印

知识库系统里，用户可以在线预览文档（PDF、图片等），也可以下载。如果不加水印：

- 用户截图或下载后可以直接传播，无法追溯到泄露源头
- 包含敏感信息的文档（薪酬、合同）缺乏保护手段

**水印的作用**：在文件上叠加当前用户信息和时间戳，即使被截图/转发，也能追溯到是谁在什么时间点获取的文件。

## 三、水印设计

### 3.1 水印内容

```
张三 @ 2026-06-27 15:32
```

由用户名 + 当前时间拼接。预览时动态生成，确保每个用户、每次看到的都是当前时刻的个性化水印。

### 3.2 水印样式

```
倾斜 -30°，浅灰色，半透明，平铺覆盖整个页面
```

**为什么倾斜？**
- 水平排列容易被裁剪或覆盖
- 倾斜的水印更难被修图工具去除

**为什么半透明？**
- 不阻挡正文阅读（透明度 60/255 ≈ 24%）
- 但截图后仍然清晰可辨

**为什么平铺？**
- 覆盖整个页面，无论裁切哪个区域都有水印

### 3.3 策略模式

```
           ┌─────────────┐
           │ 文件请求     │
           └──────┬──────┘
                  │
           ┌──────▼──────┐
           │ 判断MIME    │
           └──────┬──────┘
                  │
   ┌──────────────┼──────────────┐
   ▼              ▼              ▼
image/*      application/pdf   其他
   │              │              │
   ▼              ▼              ▼
Java 2D       PDFBox         原样返回
Graphics      Matrix 变换    (doc/ppt等)
平铺倾斜      平铺倾斜
```

**为什么用不同的技术处理不同格式？**

图片用 Java 2D（`java.awt.Graphics2D`），JDK 内置，无需额外依赖。BufferedImage 加载 → Graphics2D.drawString 画文字 → ImageIO 写出 PNG。全程 JDK 标准库，零成本。

PDF 用 Apache PDFBox。PDF 是矢量的，不能像图片一样操作像素。需要解析 PDF 文档结构，在每一页的 ContentStream 上追加文字流。

Office 文档（Word/Excel/PPT）暂不支持水印——它们需要 Apache POI 或 LibreOffice 转换，复杂度高且效果差。生产环境通常先转为 PDF 再加水印。

## 四、图片水印实现

```java
private byte[] addImageWatermark(byte[] imageBytes, String text) {
    BufferedImage image = ImageIO.read(new ByteArrayInputStream(imageBytes));

    Graphics2D g2d = (Graphics2D) image.getGraphics();
    g2d.setRenderingHint(RenderingHints.KEY_ANTIALIASING,
            RenderingHints.VALUE_ANTIALIAS_ON);   // 抗锯齿
    g2d.setColor(new Color(128, 128, 128, 60));  // 灰色 + 半透明
    g2d.setFont(new Font("Microsoft YaHei", Font.PLAIN, 20));

    // 倾斜平铺
    for (int y = -imgH; y < imgH * 2; y += 200) {
        for (int x = -imgW; x < imgW * 2; x += 400) {
            g2d.rotate(-30°, x, y);    // 先旋转坐标系
            g2d.drawString(text, x, y); // 画文字
            g2d.rotate(30°, x, y);      // 旋转回来
        }
    }
    g2d.dispose();

    ByteArrayOutputStream baos = new ByteArrayOutputStream();
    ImageIO.write(image, "png", baos);
    return baos.toByteArray();
}
```

**关键点**：
- `g2d.rotate()` 改变的是 Graphics2D 的变换矩阵，后续所有 draw 操作都在旋转后的坐标系中进行
- 旋转后再旋转回来，避免平铺网格逐渐偏移
- `RenderingHints.KEY_ANTIALIASING` 开启抗锯齿，文字边缘更平滑
- 输出统一用 PNG——PNG 支持透明度通道，水印的半透明效果才能保留

## 五、PDF 水印实现

### 5.1 和图片的根本区别

图片是栅格图（像素矩阵），PDF 是矢量图（描述性指令）。PDF 的文件内容本质是一系列绘制指令：

```
BT                          % 开始文本块
  /F1 18 Tf                % 选字体 18pt
  1 0 0 1 100 200 Tm       % 设置变换矩阵 + 位置
  (张三 @ 2026-06-27) Tj   % 绘制文字
ET                          % 结束文本块
```

PDFBox 做的事情就是往现有的指令流里追加这些指令。

### 5.2 实现

```java
private byte[] addPdfWatermark(byte[] pdfBytes, String text) {
    PDDocument doc = Loader.loadPDF(pdfBytes);

    PDType1Font font = new PDType1Font(
            Standard14Fonts.FontName.HELVETICA);

    for (PDPage page : doc.getPages()) {
        PDPageContentStream cs = new PDPageContentStream(
                doc, page, AppendMode.APPEND, true);

        // 半透明
        PDExtendedGraphicsState gs = new PDExtendedGraphicsState();
        gs.setNonStrokingAlphaConstant(0.1f);
        cs.setGraphicsStateParameters(gs);

        cs.setFont(font, 18);

        // 平铺水印文字
        for (float y = -pageH; y < pageH * 2; y += 150) {
            for (float x = -pageW; x < pageW * 2; x += 350) {
                cs.beginText();
                cs.setTextMatrix(new Matrix(
                    cos(θ),  sin(θ),
                    -sin(θ), cos(θ),
                    x, y));
                cs.showText(text);
                cs.endText();
            }
        }
        cs.close();
    }
    ByteArrayOutputStream baos = new ByteArrayOutputStream();
    doc.save(baos);
    return baos.toByteArray();
}
```

### 5.3 变换矩阵原理解析

PDF 的 2D 变换矩阵是 3×3 的仿射变换矩阵，但用 6 个参数表示：

```
[a b 0]
[c d 0]   →   新坐标: (a·x + c·y + e,  b·x + d·y + f)
[e f 1]
```

对于旋转 θ 角度：
```
a = cos(θ)   b = sin(θ)
c = -sin(θ)  d = cos(θ)
e = x位置    f = y位置
```

`new Matrix(cosθ, sinθ, -sinθ, cosθ, x, y)` 表示：以 (x, y) 为原点，将所有内容逆时针旋转 θ。效果就是文字在页面上倾斜显示。

## 六、预览 vs 下载

```java
// 预览：Content-Disposition = inline
response.setHeader("Content-Disposition",
        "inline; filename=\"" + encodeFilename(name) + "\"");

// 下载：Content-Disposition = attachment
response.setHeader("Content-Disposition",
        "attachment; filename=\"" + encodeFilename(name) + "\"");
```

| | inline | attachment |
|---|---|---|
| 浏览器行为 | 直接渲染（PDF图片在浏览器内打开） | 弹出另存为对话框 |
| 使用场景 | 在线预览 | 下载到本地 |
| 水印内容 | 用户名 + 当前时间 | "下载文件" |

两者都带水印，但预览的水印是动态的（包含当前用户+时间），下载的水印是固定的标识。

## 七、关键面试知识点

1. **为什么不用前端加水印？**
   - 前端水印可以 F12 删掉 DOM 节点，防不了
   - 后端在文件字节流层面叠加，去掉水印需要专门的图像处理工具
   - 前端水印通常是"加盖一层半透明 div"，不是真正的图片级水印

2. **图片水印为什么输出 PNG 而不是原格式？**
   - PNG 支持 alpha 透明通道，水印的半透明效果能保留
   - JPEG 不支持透明度，水印渲染后透明度信息会丢失
   - 但 PNG 文件通常比 JPEG 大——生产环境可考虑按原格式输出，对 JPEG 用不透明水印

3. **PDF 水印为什么用 Matrix 而不是简单 setTextTranslation？**
   - `setTextTranslation(x, y)` 只能平移文字
   - `setTextMatrix(Matrix)` 可以做旋转、缩放、错切等完整的仿射变换
   - 倾斜水印需要旋转，必须用 Matrix

4. **水印对文件大小的影响？**
   - 图片：输出 PNG 可能使文件变大（JPEG → PNG 转换）。生产环境建议保持原格式
   - PDF：PDFBox 追加水印指令，文件大小几乎不变（只多了几行文本指令）
